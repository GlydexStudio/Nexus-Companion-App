# Nexus configuration

Nexus is designed for Code On The Go + Android phone development. The Gradle files generated by Code On The Go remain untouched.

## 1. API keys

Start from `.env.example`:

```env
DIFY_API_KEY=
ELEVENLABS_API_KEY=
ELEVENLABS_VOICE_ID=
ELEVENLABS_MODEL_ID=
```

Do not commit `.env`.

Inside the app, use **Settings → Import .env**. The native layer reads the selected file, validates all four required values, and stores them in the Android app sandbox protected by the Android Keystore.

The credentials are never injected into JavaScript/WebView.

## 2. Three.js + three-vrm

The web runtime is local and offline after installation. On the phone project root run:

```sh
bash scripts/fetch_web_dependencies.sh
```

This pins Three.js `0.180.0` and `@pixiv/three-vrm` `3.5.5`.

## 3. VRM

Copy the supplied real model to:

`app/src/main/assets/avatars/nexus.vrm`

The avatar system is intentionally not configured with a generic fallback character.

## 4. Dify

Nexus uses Dify's blocking chat endpoint and optionally uploads a single front-camera JPEG to the Files API before attaching its returned file id to the chat request.

The app sends a local protocol envelope that asks the Agent for:

```json
{
  "text": "...",
  "emotion": {"emotion": "neutral", "intensity": 0.0},
  "memoryWrites": []
}
```

Native Kotlin validates this envelope before applying avatar state or writing memory.

## 5. ElevenLabs

Nexus uses the timestamped text-to-speech endpoint (`/with-timestamps`) so character timings can drive the available visemes. The native audio player also exposes a lightweight amplitude fallback using Android's audio visualizer.

## 6. Camera

Camera permission is requested only after the user enables **Camera / Visual Context**. The app uses the front camera only for an explicit visual-context request during a message. It does not start the camera automatically on app launch.

## 7. Security limitation

A mobile app that directly calls Dify and ElevenLabs must hold credentials somewhere available to the app at runtime. Nexus avoids source hardcoding and keeps keys out of JavaScript, but a determined attacker can still extract runtime client secrets from a client APK/device. A production deployment with a server-side secret vault and a proxy would be required for stronger secret isolation.
